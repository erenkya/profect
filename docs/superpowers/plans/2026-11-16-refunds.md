# İade Süreci Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Kullanıcının sipariş sayfasından iade talep edebildiği, adminin kuyrukta onayladığı, erişim/hediye/kontenjan/kupon etkilerinin tek işlemde geri alındığı ve Tami iadesinin tek bir fonksiyonla bağlanacağı iade sürecini kurmak.

**Architecture:** `refund_requests` tablosu + `orders.status = 'refunded'`. Saf uygunluk kuralları `src/lib/refund-rules.ts`'te; DB işleri `src/lib/refund.ts` ve `src/lib/refund-effects.ts`'te; sağlayıcı arayüzü `src/lib/payment/refund.ts` (`manual` / `mock` çalışır, `tami` "yapılandırılmadı" döner). Karar sipariş satırı `FOR UPDATE` kilidi altında, koşullu `UPDATE` ile verilir; sağlayıcı çağrısı kilidin dışındadır ve `refund_requests.id` idempotency anahtarıdır.

**Tech Stack:** Next.js 16 App Router (route handlers, server components), MySQL (mysql2), zod, nodemailer (`src/lib/mail.ts`), `node --test` (saf kurallar), `scripts/test-*.mjs` (gerçek DB + çalışan sunucu).

**Spec:** `docs/superpowers/specs/2026-11-16-refunds-design.md`

## Global Constraints

- Uygulamadan önce `node_modules/next/dist/docs/` altındaki ilgili kılavuz (route handlers, page/server components) okunur (`AGENTS.md`).
- `REFUND_WINDOW_DAYS = 14`; sipariş başına tek başvuru (`UNIQUE(order_id)`); yalnızca tam sipariş iadesi.
- Migration `db/migrations/027_refunds.sql`: yalnızca ekleyici, yeniden çalıştırılabilir (`IF NOT EXISTS` / `MODIFY` ENUM), mevcut satırlara dokunmaz.
- Saf kural dosyaları `server-only` içermez ve içe aktarmalarda `.ts` uzantısı kullanır (bkz. `src/lib/gift-rules.ts`); testleri `src/lib/*.test.ts` (`npm test`).
- Kart verisi saklanmaz. Arayüz metinleri ve kod yorumları Türkçe.
- Engel nedenleri sabit: `not_paid`, `free_order`, `window_expired`, `already_started`, `gift_claimed`, `seats_assigned`, `request_exists`. Admin yalnızca `already_started` ve `window_expired` engellerini, gerekçe notuyla aşabilir.
- "Başladı mı" = tamamlanmış ders ya da `WATCH_MIN_BYTES` (512 KB) üstü video akışı (`isWatched`, `src/lib/company-rules.ts`), yalnızca `paid_at` ve sonrası için.
- Erişim silme yalnızca `source = 'purchase'` kayıtlar için ve başka ödenmiş/iade edilmemiş sipariş aynı kursu karşılamıyorsa.
- İade tutarı = `orders.amount` (indirim sonrası tahsil edilen).

## Review Focus

1. Aynı onay iki kez / eş zamanlı gelirse tek iade olmalı, ikinci istek `bad_state` almalı (Task 5 testi).
2. Alıcı satın almadan önce ücretsiz önizleme izlemişse iade engellenmemeli (Task 3 testi).
3. `paid_at` boş eski ödenmiş sipariş: `created_at`'e düşülmeli, hata verilmemeli (Task 3 testi).
4. İade edilmiş siparişe `fulfillOrder` (admin "onayla" API'si ya da Tami callback'i) erişimi yeniden açmamalı (Task 5 testi).
5. Kursa sipariş dışı yoldan (admin/hediye) sahip kullanıcının erişimi iade yüzünden silinmemeli (Task 6 testi).
